OGSM 总表

Objective · Goals · Strategies · Measures

OGSM 是战略屋的文字化展开：定性的方向（O）、定量的目标（G）、实现路径（S）、衡量标尺（M）。

维度内容
O 战略目标在金融行业确立「AI 原生数据治理 + 监管报送」差异化竞争优势，实现业务规模化、可复制、高质量增长。
G 量化目标 G1 单项目交付周期：以数据治理项目为例，周期由6个月缩短至2个月
G2 单项目现场交付人员：以数据治理项目为例，周期由3-5人减少至1人
G3 客户验收满意度 ≥ 90%
S 关键策略 S1 平台 AI Native 化改造（MCP/API/NL2Action，让 Agent 可调用平台能力）
S2 打造标准化 OPP 交付方法论 + PM 能力模型并跑通试点
S3 建设金租行业知识库（监管制度 + 数据治理标准/质检/分类分级）
S4 售前体系升级（AI 专家团对外宣讲 + 桌面 Agent 演示）
S5 开发建设 AI 专家团（治理/报送专家能力模型，封装专家知识、技能与 Tools 工具）
M 衡量指标 M1 平台改造完成模块数 / 上线 MCP 工具数（≥8 模块、≥40 工具）
M2 知识库条目：监管制度 、金租标准 、质检规则
M3 OPP 试点项目数 / 平均交付周期 / 现场交付人员数量
M4 商机数 / 转化率 / 标杆案例数
M5 客户满意度 / 复购率 / 营收达成率
M6 专家团建设：治理/报送专家角色数与能力模型，封装专家知识/技能/Tools 工具数

资源需求 · Resource Map

落地战略需要哪些资源

战略屋的"地基"落到资源上，需人力、技术平台、知识数据、组织机制四类协同投入。

人力资源

角色与编制

• 平台 AI 化研发：3–4 人（前端/后端/接口/MCP/RAG算法）
• 交付工程师：5–8 人
• 售前专家：2–3 人
• 项目管理（PMO）：1 人
• 产品经理（平台 AI 化）：1 人
• 知识运营：1 人

技术 / 平台

基础设施

• 桌面级 Agent 平台EsXWork
• 睿治数据治理平台 + 统一监管报送平台测试/演示环境
• 向量数据库 + RAG 检索基础设施 + 开发联调环境
• 数据中台/样例数据源（核心、信贷、财务、数仓）用于验证

知识 / 数据

内容资产

• 监管制度原文：EAST / 1104 / 人行大集中 / 金数 / 利率报备 / 征信 / 外管 / 地方特色
• 金租行业样本：元数据标准、业务术语、参考数据、主数据
• 历史项目资产：蓝图、方案、质检规则、映射文档（脱敏复用）
• 方法论与模板：DAMA / DCMM、实施模板库

组织 / 机制

保障体系

• 跨部门协同机制：与平台研发部、交付部建立季度对接与需求优先级通道；
• 考核与激励：OPP 项目计奖、标杆案例专项奖、知识贡献积分；
• 领导授权与复盘：部门经理对资源调度与对外承诺的授权，月度 OKR 复盘、季度战略校准；
• 生态合作：与监管科技、咨询机构形成联合方案。
